# Plastile 0.1.0 alpha: release notes (draft)

**Draft, not released.** Plastile is licensed under GPL-3.0-or-later
([ADR-012](../design/DECISIONS.md#adr-012-license-and-upstream-reuse-are-deliberate), `LICENSE`; every
distributable file carries the licence text). This alpha comes before gate G3
([ADR-024](../design/DECISIONS.md#adr-024-an-alpha-before-g3-declaring-kwin-67-and-68)) and is not the
qualified release; the open G3 gates are in the [G3 checklist](../status/G3_CHECKLIST.md). The
[steps before tagging](#before-tagging) are at the end.

## What it is

Automatic tiling for KDE Plasma 6 on Wayland that keeps KWin as the window manager. Plastile is a KWin
script: it decides where windows go and asks KWin to put them there. It does not replace KWin, and it leaves
fullscreen, maximize, minimize, native quick tiling and windows you float to you.

## What is in it

- Layouts: master/stack (default), BSP, monocle and floating, chosen per context (screen, desktop and
  activity) and switched with the window order kept.
- Keyboard commands for focus, swap, grow/shrink, master count, BSP rotate/mirror/equalize, send to
  desktop or screen, floating, suspend/resume and reconcile ([SHORTCUTS](../user/SHORTCUTS.md)).
- Pointer drags: drop a tile on another to swap them; Meta+right-drag moves the shared divider.
- Validated configuration in a settings dialog or a JSON document, with rules and per-context overrides.
  Invalid configuration is rejected and the previous one kept ([CONFIGURATION](../user/CONFIGURATION.md)).
- Windows that open maximized are tiled once; a later maximize is respected
  ([ADR-021](../design/DECISIONS.md#adr-021-a-window-that-arrives-maximized-is-un-maximized-and-tiled)).
- Multiple monitors, mixed refresh rates, fractional scaling, panels, per-screen virtual desktops and
  activities.
- Saved layout preferences (layout choice, master ratio and count, floated windows' positions) through an
  optional D-Bus helper, `plastile-state`, built from source. Without it Plastile works and keeps them in
  memory ([INSTALL §2a](../user/INSTALL.md#persistence-helper)).
- *Explain active window* opens an inspector that says why a window is where it is
  ([TROUBLESHOOTING](../user/TROUBLESHOOTING.md)).
- **Plastile Motion**, a separate optional KWin effect, installed disabled, that animates how windows slide
  into place ([ADR-023](../design/DECISIONS.md#adr-023-window-motion-is-an-optional-transform-only-kwin-effect-plastile-motion)).
  Plastile itself never animates.

**Experimental, off unless selected:** the scrolling and zones layouts
([ADR-014](../design/DECISIONS.md#adr-014-start-m8m9-as-experimental-opt-in-layouts-before-g3-physical-sign-off)).
They are tested in nested KWin only. Whether they ship in this alpha, labelled experimental, is an owner
decision; these notes assume they do.

On KWin 6.8.0 in CI, in about half of the repetitions (7 of 14), KWin itself grew by 35–77 MiB over 100
reloads of an empty script ([q09-kwin68-control](../status/evidence/q09-kwin68-control.json)), so CI's
reload-memory checks fail in some runs there. It has been observed only over repeated reloads. It was not
seen on 6.8.1 in two nested full-suite runs on the reference host (0.35 and 0.43 MiB over 100 reloads of
Plastile), a different environment from the 6.8.0 CI job; the empty-script control has not been run on
6.8.1. Other versions are untested.

## Known limitations

The full list is in [TROUBLESHOOTING](../user/TROUBLESHOOTING.md#known-limitations). The ones most likely to
matter:

- **Latency at high refresh rates.** At 144 Hz a grow/shrink became visible a median 11.5 ms later than
  KWin's own quick tile (p95 +30 ms); Plastile's request reached the application within 0.6 ms, and the extra
  time is between the applications' commits and KWin presenting them (cause open). Focus is slower than
  KWin's window switch with Aurorae decorations (+10.3 ms median at 144 Hz), mostly the decoration's
  re-render; 1.2 ms at equal window size is unexplained. At 60 Hz every workload passed. The 100 Hz run is
  incomplete.
- **Not checked physically:** unplugging a monitor (it passes nested); system suspend (no nested
  equivalent); uninstall; the scrolling and zones layouts; two identical monitors; VRR; the hidden-desktop
  panel fix; in-app actions on tiled windows (titlebar buttons, tabs, turning a border off and on); clicking
  through the settings dialog; a terminal launched the owner's usual way that opens maximized. Plastile Motion
  was only reported "works" by the owner, not judged per refresh rate.
- **Saved state is partial by design:** window order and BSP structure are not saved; the scrolling strip and
  zone assignments last for the session only.
- **KWin behaviour:** Apply in the settings dialog needs *Reload configuration* to reach the running script;
  an upgrade needs a log out and in to run the new version; `plastile.*` shortcut entries outlive removal
  until cleaned up ([INSTALL §6](../user/INSTALL.md#6-uninstall-cleanly)).
- **Shortcut conflict:** `Meta+Ctrl+S` is also bound by the Wacom tablet settings where they are installed.
- **Known minor items** left from the bug-hunt review, for example floating windows shift when a panel moves
  to the opposite edge, and a drag during the at most 750 ms float-restore wait is overwritten when the
  restore is written ([STATUS](../status/STATUS.md)).

## Install

One line, once the release is published:
`curl -fsSL https://raw.githubusercontent.com/Yejashi/plastile/main/install.sh | sh` (add `-s -- --with-helper`
for saved preferences; [INSTALL](../user/INSTALL.md#quick-install-from-a-release)). NixOS: the flake's
`nixosModules.default` ([INSTALL](../user/INSTALL.md#nixos)). From the repository: `npm ci && npm run build`,
then `tools/install.sh install`, and `tools/install.sh install-helper` for saved preferences. `tools/release.py` builds the distributable
files, reproducibly (`--check`):

- `dist/plastile-0.1.0.kwinscript`: the script (`kpackagetool6 --type KWin/Script --install`);
- `dist/plastile_motion-0.1.0.zip`: the optional effect (`kpackagetool6 --type KWin/Effect --install`);
- `dist/plastile-state-0.1.0.tar.gz`: the helper's source.

The alpha and the release candidate share version 0.1.0; the qualified release will carry a higher version
(ADR-024). Until then the commit and the sha256 sums identify the alpha's files.

## Before tagging

1. ~~Licence~~ **done (2026-10-26): GPL-3.0-or-later** (ADR-012). Upstream code was used as reference only
   ([HANDOFF §7](../status/HANDOFF.md#7-owner-decisions-still-open)); no copied code is known. Plastile has no runtime dependencies; the
   bundle adds only esbuild's object spread/rest helpers (esbuild, MIT). The helper links Qt 6 (LGPL-3.0 or
   GPL). `LICENSE` is at the repository root, both `metadata.json` files say `GPL-3.0-or-later`, and
   `tools/release.py` puts `LICENSE` into each of the three files.
2. **Scrolling and zones** in or out (owner, ADR-014).
3. **Some days of normal use** of the alpha build on the reference desktop with no new Plastile errors in the
   journal (`journalctl --user -b | grep plastile`).
4. Remove "draft" from this file, then tag and push: `git tag -a v0.1.0-alpha -m "Plastile 0.1.0 alpha" &&
   git push origin v0.1.0-alpha`. The [release workflow](../../.github/workflows/release.yml) builds the three
   files with `tools/release.py --check`, writes `SHA256SUMS` and creates a draft pre-release; review it and
   click *Publish release*. From then on the quick install (`install.sh`) installs it.
