# Script API profile: KWin 6.7.5, declarative scripts (T01 / E03)

**Scope:** what a *declarative* (QML) KWin script can actually reach in the installed build (tag `v6.7.5`, [environment](ENVIRONMENT.md)). Plain-JS scripts use a different wrapper (`QtScriptWorkspaceWrapper`), and this profile does not cover them.

**Evidence labels:**
- **R** — runtime introspection or behaviour from [`probes/capability`](../../probes/capability), run in nested KWin 6.7.5. Raw results: [evidence/capabilities-a.json](evidence/capabilities-a.json) and [evidence/capabilities-b.json](evidence/capabilities-b.json).
- **S** — observed source at tag `ab7df7cc`.
- **M** — measured by the timing, lifecycle or constraints probes ([M0 probe report](M0_PROBE_REPORT.md)).
- **N** — exercised by the named nested integration scenarios (`python3 tests/integration/run.py --list`), in nested KWin 6.7.5 unless the row says otherwise. "Used, not separately measured" means the adapter connects the signal but no scenario isolates it. Nothing in this profile has been checked in a physical session.

## Required adapter operations

| Need | Real surface | Evidence | Semantics and caveats |
|---|---|---|---|
| Enumerate windows | `Workspace.windows` (QQmlListProperty) | R | **`Workspace.windowList()` does not exist in declarative scripts.** It belongs to the plain-JS wrapper and throws `TypeError`. `windows` is not a JS `Array` (`Array.isArray` is false); index it or use `Array.from`. |
| Window lifecycle | `Workspace.windowAdded(w)`, `windowRemoved(w)`; `w.closed` | R/S | Fires when the window is managed (mapped). Connections must be disconnected explicitly; see "Lifetime" below. |
| Stable window ID | `w.internalId` (QUuid) | R | `String(w.internalId)` gives a stable 38-character `{uuid}` across reads. It is session-local, not durable. |
| Classification | `normalWindow, dialog, utility, specialWindow, transient, transientFor, modal, popupWindow, windowType, resourceClass, resourceName, desktopFileName, windowRole, managed, deleted`, plus the type booleans | R | For Wayland clients, `resourceClass == resourceName == desktopFileName ==` the xdg app_id (Qt apps: `org.qt-project.qml6`, `qml`). |
| Classification changes | `w.windowClassChanged`, `w.transientChanged`, `w.modalChanged`; `w.caption`, `w.captionChanged` | R, N | The adapter re-reads metadata and constraints on the first three. `captionChanged` is connected only while title rules are active and updates the title alone. `captionChanged` is exercised by the retitle checks in `classify-rule-title-T16` and `classify-rule-title-reconfigure-T16`. The class, transient and modal signals are used, not separately measured: no scenario changes them after a window maps. |
| Focus | `Workspace.activeWindow` (R/W), `windowActivated(w)`, `w.active`, `w.activeChanged` | R | Assigning `activeWindow` is used to target the quick-tile slots. |
| Outputs | `Workspace.screens`, `screenOrder`, `activeScreen`, `screenAt(point)`, `screensChanged`, `screenOrderChanged`, `virtualScreenGeometryChanged`, `w.output`, `w.outputChanged` | R, N | The adapter schedules one topology refresh on `screensChanged`, `screenOrderChanged`, `virtualScreenGeometryChanged` and each output's `geometryChanged`. Output changes are covered by `outputs-O01`, `output-reorder-O03`, `unplug-O04`, `replug-identity-O05` and `output-*-origin-G02`. `virtualScreenGeometryChanged` is used, not separately measured: those scenarios also emit `screensChanged`, so they do not isolate it. Output object exposes `name, geometry, devicePixelRatio, manufacturer, model, serialNumber`, plus `geometryChanged, scaleChanged, aboutToChange, changed`. It has **no UUID property** (KScreen UUIDs are not script-visible). Output identity must use connector name + manufacturer/model/serial; the virtual backend leaves the last three empty. |
| Move window to output | `Workspace.sendClientToScreen(w, output)` | R, N | **`w.output` is read-only:** assignment throws `TypeError: Cannot assign to read-only property "output"`. Transfer works (`outputs-O01`, `follow-on-send-T24`), and the frame change arrives before `outputChanged` (`outputs-O01`). |
| Desktops | `Workspace.desktops`, `currentDesktop`, `desktopsChanged`, `currentDesktopChanged(prev, cur, output)`; `w.desktops` (R/W list), `w.onAllDesktops`, `w.desktopsChanged` | R/S | `VirtualDesktop.id` is a 36-character UUID string, a stable ID. It also has `name` and `x11DesktopNumber`. `VirtualDesktop.nameChanged` lets name-matched overrides follow a rename (scenario `config-desktop-rename-Q02`). |
| Per-output desktop | `Workspace.currentDesktopForScreen(o)`, `setCurrentDesktopForScreen(d, o)` | R | Present and working; returns the global desktop when per-output desktops are off. The live session has `perOutputVirtualDesktops=false`. |
| Activities | `Workspace.activities`, `currentActivity`, `activityAdded/Removed`, `activitiesChanged`, `currentActivityChanged`; `w.activities` (R/W), `w.activitiesChanged` | R, N | Without the Activities service the list has one entry, the nil UUID, and `currentActivity === ""`. With a private `kactivitymanagerd`, adding or removing an activity emits `activityAdded`/`activityRemoved` and `activitiesChanged(id)`, and the adapter schedules a topology refresh on `activitiesChanged`. Starting the service late emits only `currentActivityChanged`, with no `activitiesChanged` and no `w.activitiesChanged`. An all-activities window reads back as `w.activities = []`, and the assignment emits `w.activitiesChanged` with no arguments. `w.onAllActivities` is undefined. The adapter re-reads membership on `w.activitiesChanged`. Scenarios: `activities-E08`, `activities-late-service-E08`, `activities-add-second-E08`. |
| Usable area | `Workspace.clientArea(option, output, desktop)`, `clientArea(option, window)` | R, N | Enum values: `Workspace.PlacementArea=0`, `MaximizeArea=2`, `FullScreenArea=4`, `WorkArea=5`. They are **not** on the `KWin` context object. Returns a rect with `x/y/width/height`. Panel reservation was measured with a layer-shell panel fixture: the area shrinks once, with no double subtraction (`workarea-panel-add-remove-O07`, `workarea-panel-before-load-O07`, `workarea-two-panels-O07`, `workarea-panel-one-output-O07`). There is no script-visible work-area signal, so the adapter compares areas when a dock window is added, moves or is removed. |
| Direct frame request | `w.frameGeometry = Qt.rect(...)`; plain `{x,y,width,height}` objects are also accepted | R, M | A **position-only** write emits `frameGeometryChanged` **synchronously inside the setter**, and the readback is updated at once. A **resize** write emits nothing synchronously; readback keeps the old size until the client commits (configure, ack, commit). KWin geometry is **floating point**: values such as `466.666…` and `400.00000000000006` were observed at scale 1. |
| Frame vs client | `w.frameGeometry`, `w.clientGeometry`, `w.bufferGeometry` | R | With Breeze SSD the frame is the client plus a 28 px titlebar and no side borders. With CSD (or no decoration plugin) frame == client. Decoration changes arrive as `w.decorationPolicyChanged`, `w.decorationChanged`, then `w.clientGeometryChanged` (measured order); the margin is current only at that `clientGeometryChanged`, which the adapter uses to refresh frame-space constraints. |
| Constraints | `w.minSize`, `w.maxSize` (no NOTIFY), `w.resizeable`, `w.moveable`, `w.fullScreenable`, `w.maximizable` | R, M | `minSize`/`maxSize` are in **client** coordinates. Unconstrained max is reported as `2147483647`. **KWin does not clamp script frame requests to `minSize`** (see E07 in the report). Because `minSize`/`maxSize` have no NOTIFY, the adapter re-reads them on `w.maximizeableChanged` (emitted on every xdg-toplevel min/max size change; for X11 only when the maximize action flips, measured 6.7.5). |
| Maximize / fullscreen / minimize | `w.setMaximize(v, h)`, `w.maximizeMode` (R), `maximizedChanged`; `w.fullScreen` (R/W), `fullScreenChanged`; `w.minimized` (R/W), `minimizedChanged`; `w.hidden`, `hiddenChanged` | R/S, N | State transitions were measured nested: fullscreen, minimize, maximize and restore are respected (`states-L09-L12`). The adapter also connects `hiddenChanged` to the same state refresh. That connection is used, not separately measured. |
| Interactive move/resize | `w.move`, `w.resize` (R), `moveResizedChanged`, `interactiveMoveResizeStarted/Stepped/Finished` | R, N | The virtual backend has no input device of its own. These signals were exercised with real input through KWin's EIS endpoint (`drag-I01-I02`, `resize-I03`, `drag-teardown-I04`, `drag-output-removal-I04`, `resize-rapid-keys-I05`, `live-resize-T29`). Not checked in a physical session. |
| Native tile root | `Workspace.rootTile(output, desktop)`; `Workspace.tilingForScreen(output).rootTile` | R | Present. The nested default root has 3 children (0.25/0.5/0.25), `padding 4`, `minimumSize {0.15, 0.15}`, `layoutDirection 1`, `canBeRemoved false`. `tilingForScreen(o).rootTile === rootTile(o, currentDesktopForScreen(o))`. |
| Native tile members | `relativeGeometry` (R/W), `absoluteGeometry`, `absoluteGeometryInScreen`, `padding`, `minimumSize`, `layoutDirection`, `tiles`, `windows`, `parent`, `isLayout`, `canBeRemoved`, `positionInLayout`; `split(dir)`, `remove()`, `resizeByPixels`, `moveByPixels`, `manage(w)`, `unmanage(w)`, `pick()` (root only); `TileManager.bestTileForPosition` | R, N | Present. `split`/`remove` mutation counts per workload are recorded in the G1 native spike (`evidence/spike-native.json`). Tree edits and manage/unmanage are covered by `native-tree-edit-L14`, `native-manage-L14` and `native-unmanage-config-L14`. The time cost of an individual `split`/`remove` is not separately measured. |
| Native association | `tile.manage(w)` → bool, `tile.unmanage(w)` → bool; `w.tile` (R/W, deprecated setter), `tileChanged`, `requestedTileChanged` | R, M | `manage` returned `true` and `w.tile` became the leaf, but **no `tileChanged` was emitted synchronously**; `requestedTileChanged` also exists. **A native quick-tile is a `Tile` association (`w.tile !== null`).** A direct `frameGeometry` write does **not** clear it; `w.tile.unmanage(w)` does, and returns true. |
| Native quick tile | `Workspace.slotWindowQuickTile{Left,Right,Top,Bottom,TopLeft,…}()` act on the active window | R, M, S | Repeating the current mode is a no-op (or shifts to the adjacent output if one exists). Left from top-left was also a no-op. |
| Shortcuts | `ShortcutHandler { name; text; sequence; onActivated }` | R, S | Registers a `QAction` in kglobalaccel component **`kwin`**. Invocable over D-Bus with `org.kde.kglobalaccel /component/kwin invokeShortcut(name)`. **Registration persists in `kglobalshortcutsrc`** after unload, so a probe in the live session would leave entries in the user's file. |
| Script config | `KWin.readConfig(key, default)` reads `kwinrc [Script-<pluginName>]`; `Options.configChanged` (the QML `Options` singleton) | R, N | Values arrive as strings or bools; compare with `String(v) === "true"`. The runtime re-reads and validates its configuration on `Options.configChanged`, which KWin emits after a reconfigure. Measured nested (perf workload P13, `evidence/perf-workloads-20261017T211206.json`): one signal per D-Bus `reconfigure`, arriving about 213 ms later, which is KWin's 200 ms reconfigure timer. Scenarios: `config-Q01`, `reload-config-D9-Q04`, `classify-rule-title-reconfigure-T16`. |
| Deferred work | `Qt.callLater(fn, ...args)` | R, M | Coalesces by **function identity**: 1000 calls with one stable function ran once; 1000 fresh closures ran 1000 times. |
| Timers | QML `Timer` (`interval`, `repeat`, `restart`, `stop`) | M | Not quantized to a 16 ms animation tick in this configuration (see the report). |
| Timestamps | `Date.now()` only (1 ms steps) | R | **No `performance.now()`, `setTimeout`, `queueMicrotask` or `globalThis`.** Sub-millisecond timing needs the measurement-only `Plastile.Measure` module (nested sessions only). |
| Loading | `org.kde.kwin.Scripting.loadDeclarativeScript(path, plugin)` then `/Scripting/Script<N> run`; `unloadScript(plugin)`; `isScriptLoaded`; `start()` | R, S, M | Package entry is **hard-coded** to `contents/ui/main.qml` for declarative scripts. Autoload at startup and disable/re-enable via `[Plugins] <id>Enabled` + `Scripting.start()` work. A package installed **after** KWin started is found by `start()` only after about 20 s (measured: loaded 20.6 s after installation, 5 earlier calls missed it; `package-post-start-discovery-T32`); a cached package listing that expires is the suspected cause (**inference**). |

## JavaScript language level in KWin's QV4 (Qt 6.12)

Measured by compiling each snippet with `new Function` inside the declarative script engine.

**Supported:** `let`/`const`; arrows; classes (constructor, accessors, static methods, `extends`/`super`); template literals; default parameters; `**` and `**=`; basic and array-rest destructuring; call/array spread; computed keys; shorthand methods; generators; `for…of` (including `Map` entries); labeled break; `Map`, `Set`, `WeakMap`, `Symbol`, `Promise`, `Proxy`, `Reflect`, typed arrays; `?.` and `??`; numeric separators; `Array.prototype.includes/find/findIndex`, `Array.from`, `Object.assign/values/entries`, `String.prototype.includes/startsWith/padStart`; `console.time`.

**Not supported (parse or type errors):** class fields (public and `#private`); object rest/spread (`{...o}`); `async`/`await`; logical assignment (`??=`, `||=`); BigInt; optional catch binding (`catch {}`); `Array.prototype.flat/flatMap/at`; `Object.fromEntries`; `WeakRef`; `structuredClone`; `globalThis`.

**Consequence for the TypeScript core (T09):** emit a conservative target (ES2017-level syntax) and downlevel object spread/rest, class fields, `async` and logical assignment. Forbid `flat`, `at`, `fromEntries` and `globalThis` with lint or type-lib settings rather than polyfilling in the hot path. Run the compiled bundle through this probe's parser in nested KWin as a build gate.

## Lifetime facts that constrain the adapter

- Unload (`unloadScript`, or disabling via config) calls `deleteLater()` on the script object (S), and `Component.onDestruction` runs (R).
- All declarative scripts share **one `QQmlEngine`** (S).
- **A plain JS closure connected to a `Workspace` signal survives script unload and keeps firing** (M: the leak-control run). Each reload adds another live dead-instance closure. Every connection must therefore go through an owned registry and be disconnected in teardown. This is mandatory, not defensive.
- A `Qt.callLater` queued during `Component.onDestruction`, and a running QML `Timer` at unload, did **not** fire after teardown (M).
- After unload, kglobalaccel still accepts `invokeShortcut` for the destroyed action, and no handler runs (M).

## KWin behaviours found on the reference machine and in KWin 6.8 CI (2026-10-18)

The first full nested run on the reference machine's own KWin 6.7.5 (real GPU) and the hosted KWin 6.8.0 job surfaced behaviours the QPainter sandbox did not. Each is handled in code, with a regression test.

| Behaviour | Version | Label | Consequence in Plastile |
|---|---|---|---|
| A GTK client-side-decorated X11 window's client geometry includes its shadow (`_GTK_FRAME_EXTENTS`), so frame − client is **negative** (−44 for zenity, −50 for gnome-calculator) | 6.7.5 | measured | Frame-space constraints use the signed margin (bounded below by 0); `realapps-*-x11` |
| An X11 frame write is applied **inside the setter**; `frameGeometryChanged` echoes the requested size before the client answers with its own ConfigureRequest | 6.7.5 | measured | The echo is not treated as the client's answer; the later self-resize re-reads constraints |
| `WM_NORMAL_HINTS` changes after `windowAdded` emit **no** script-visible signal unless the allowed actions flip (`maximizeableChanged`) | 6.7.5 | measured (60+ signals hooked) | Constraints are re-read when a client answers a request with another size |
| With a real GPU, `decorationChanged` arrives ~100 ms after the first tile write and may not be followed by a geometry change | 6.7.5 | measured | The one-shot margin watcher can stay armed while idle; counters report it as `transientConnections` |
| Default Meta+left/right-drag actions are "Activate, raise and move/resize" (`kwin.kcfg` CommandAll1/CommandAll3); 6.7.5 used "Move"/"Resize" | 6.8.0 | observed source | The dragged window is the command target; a mid-drag slot change voids the drag's edges (`interaction-superseded`) |
| `XdgToplevelWindow::handleRoleCommit` runs `confineInteractiveMove` on every configure-acknowledging commit, pulling off-screen windows into the work area | 6.8.0 | observed source; measured in CI | Parked scrolling windows are re-parked through their own bounded allowance |
| `EisContext::updateScreens()` replaces the libeis device under a held button without releasing it; libeis then drops the release and KWin's move stays open | 6.7.5 | observed source; measured (with and without Plastile) | Test-input artifact (a physical mouse is unaffected); the I04 scenario delivers the release through the new device. Persistence postponement is bounded (30 s) so a stuck interaction cannot become polling |
| Qt searches `QML2_IMPORT_PATH` before `QML_IMPORT_PATH` | Qt 6.11/6.12 | observed source | Test environments must shadow modules on both (`persist-no-qtcore-Q05`) |
